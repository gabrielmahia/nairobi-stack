# Project Baobab — Engineering Doctrine

**Status: permanent strategic DNA · applies to all work in this ecosystem**

This institute's optimization target is not code. It is **capability**: reusable
infrastructure, interoperability, developer productivity, institutional capability,
open knowledge, ecosystem health, long-term maintainability.

**Build railroads, never trains.** Applications exist only as reference
implementations proving the rails work.

## Before creating anything, in strict order
1. Contribute upstream.
2. Extend an existing project.
3. Fork and improve.
4. Standardize competing work.
5. Create new — only if no reusable solution exists.

Never duplicate mature infrastructure. Repository creation is expensive;
maintenance is a first-class engineering activity.

## The Gap Register
Every project originates from a validated gap recorded in
[GAP_REGISTER.md](GAP_REGISTER.md). Each entry answers: why does the gap exist,
who benefits, what already exists, what depends on it, and what reusable form it
should take (MCP, connector, dataset, standard, benchmark, decision engine).

## Non-negotiables
- Every repo is assumed maintained for ten-plus years.
- Documentation, architecture, governance, tests, and standards **are code**.
- Every output carries enough context that another engineer can continue the
  work without its original authors.
- Treat GitHub, Hugging Face, Kaggle, MCP registries, and open-data ecosystems
  as one organism: observe, learn, improve.
- Measure success only by the increase in reusable engineering capability
  created for future builders.

## The immutable decision rule
**If this extends the railroad, build it. If it merely builds another train,
redesign it.**
